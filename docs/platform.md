# The platform: one voice engine, many hosts, pluggable identity

## What this is

A standalone, local-first **voice platform** that can power several independent applications.
It is not any one application's voice engine, and nothing in the synthesis or recognition path
knows which application is talking. Any project is a *host*: it supplies one function —
utterance in, reply text out — and owns its own state, memory, permissions and UI.

The name `nativevoice` is a package label, not a product boundary; renaming the import namespace
is an open decision (`DECISIONS.md` N1).

## Three separations that define the architecture

**1. Engine from identity.** A synthesis engine offers *speaker slots* — Kokoro's `voices.bin` is an
anonymous array of 103 embeddings with no names and no per-speaker language tag. A slot is not a
voice. `voices.VoiceIdentity` is the installable, versioned package a host selects: identifier,
display name, supported languages with per-language status, accent and style, required engine and
model, quantization and sample-rate compatibility, provenance and permissions, measured
quality/latency/resource figures, and install/update/removal records. It resolves to an engine-facing
`VoiceReference` carrying the **slot number**, so no engine ever parses a display name to find an
embedding — that coupling existed and was removed.

**2. Catalogue from selection.** The identity catalogue is shared; each host's default and its data
live under `HostProfile.root`. Resolution order is explicit request → host default → platform
default, and an explicitly requested voice that is not installed is an error, never a quiet
substitution: a host that asks for its own narrator and gets somebody else's has been told a lie in
a language it can hear.

**3. Platform from host memory.** The engine persists nothing. Ten full conversations in an empty
directory create no file; the turn window is a bounded in-memory deque; `diagnose()` reports
`history_persisted: false`. Each host owns its own persistent memory, and the platform
duplicates none of it.

## Consent applies to people, not to embeddings

`ProfileInvalid: a voice reference needs consent on record before it can speak` used to fire for
*every* voice, which meant an installed identity from an Apache-2.0 checkpoint could not speak at
all. The rule is now what it should have been: a reference carrying **recorded audio** — a real
person's voice — requires a consent record; an installed model slot is governed by provenance and
permissions instead. Both paths are pinned by tests.

## What two hosts actually looks like

`tools/platform_demo.py` runs two hosts through the same compiled engines, each with its own
answer, sink, identity and data root, inside an offline guard. Both hosts spoke (`PASS`), each
from a different speaker slot, with zero network attempts. The recorded run names them by their
machine identifiers, `ultron` and `fieldmind` (`artifacts/platform/platform-run.json`). Those
keys are demo and evidence identifiers held inside committed output, not product names, and
they are not renamed here.

A second voice is not named or offered on a guess. The tool synthesises a probe sentence with slot 7,
transcribes it back with the approved ASR model, and records `MEASURED` only if the round-trip clears
0.15 WER — otherwise the identity is written as `MEASURED_FAILED` and selection refuses it. Both
slots measured 0.000 on the probe here. Neither is given a display name, because the asset provides
none and an invented name is metadata a later reader would trust as provenance.

## Model ownership, staged rather than asserted

The goal is our own checkpoints, and wrapping somebody's model does not meet it. The staged path,
with the current baseline measured first:

| Stage | What it produces | Blocked on |
|---|---|---|
| 0. Measured baseline | Whisper-base / Kokoro-slot-0 numbers per language | **done** |
| 1. Owned corpus | Paired audio+transcript generated by our own synthesis, ASR-verified, digest-pinned, with per-clip provenance recorded — the licence and consent basis is recorded, not asserted | built; training stays blocked until boundary evidence exists and the rights questions are ruled on |
| 2. Fine-tune / adapt ASR | Our checkpoint from an MIT-licensed base on our corpus | torch install; approval for the base checkpoint's terms |
| 3. Distil a smaller TTS | A CPU-viable model that meets RTF < 1 | a teacher licence that permits distillation, plus compute |
| 4. Train from scratch | Fully owned weights | data + GPU we do not have; not attempted to earn a label |

Stage 1 is the step that changes the asset conversation, because synthetic data from an Apache-2.0
model that we generate and verify ourselves is data we can describe the provenance of. Stages 2–3
require your approval for a new checkpoint before anything is downloaded, and each will be compared
against the stage-0 baseline before anything is replaced. Providers stay interchangeable behind
`Transcriber` / `SpeechSynthesizer`, so a new model is an adapter, not a rebuild.

## Multilingual status is a ledger, not a roadmap claim

Per-language, per-task, per-model capability with six statuses — `measured`, `measured_failed`,
`declared`, `partial`, `unsupported`, `no_model` — is the only place a language claim lives. The 60-language
target is recorded as a target. Bengali and Hindi synthesis and acoustic language identification stay
documented gaps until an appropriate asset is approved and its behaviour is measured.

## Profile honesty

Profiles are seeded, not certified. One field of five (peak resident memory) has real measurements
behind it; buffer size, concurrency and quantization policy are unbenchmarked, so all three profiles
still report `provisional: True`, and `require_validated()` raises. A single benchmark cannot certify
a profile — that was an actual defect (`docs/audit-register.md` A6), not a hypothetical one.
